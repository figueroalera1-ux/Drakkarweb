# DESIGN SYSTEM

Versión: 1.0

---

# Objetivo

Este documento define el lenguaje visual de Tiendas Drakkar.

Todo componente deberá seguir estas reglas.

La prioridad será la claridad, la elegancia y la facilidad de mantenimiento.

No se permitirá agregar componentes únicamente por razones estéticas.

Cada elemento deberá mejorar la experiencia del usuario.

---

# Filosofía visual

Tiendas Drakkar deberá transmitir:

• Confianza.

• Profesionalismo.

• Modernidad.

• Cercanía.

• Solidez.

Nunca deberá sentirse como una plantilla genérica.

Nunca deberá parecer un marketplace.

Nunca deberá parecer un sitio improvisado.

---

# Personalidad visual

Si Tiendas Drakkar fuera una persona sería:

Un joven de aproximadamente 21 años.

Profesional.

Seguro de sí mismo.

Actualizado.

Tecnológico.

Amable.

Empático.

Con iniciativa.

Siempre dispuesto a ayudar.

Nunca arrogante.

Nunca agresivo.

---

# Estilo general

El diseño deberá ser:

Minimalista.

Limpio.

Espacioso.

Elegante.

Muy visual.

Las fotografías deberán comunicar más que los textos.

---

# Principios de diseño

• Mucho espacio en blanco.

• Pocos colores.

• Tipografía grande.

• Fotografía de alta calidad.

• Pocos elementos por pantalla.

• Navegación extremadamente sencilla.

---

# Componentes reutilizables

Todo deberá construirse mediante componentes reutilizables.

Ejemplos:

Header

Hero

Carrusel

Tarjeta de categoría

Tarjeta de producto

CTA

Bloque de confianza

Preguntas frecuentes

Footer

Formulario

Botón

Badge

Etiqueta

Galería

Modal

Toast

Loader

---

# Sistema de espaciado

Todo el sitio deberá utilizar una escala consistente.

No deberán existir márgenes o espacios definidos de forma arbitraria.

---

# Sistema de botones

Existirán únicamente tres botones principales.

Botón Primario.

Botón Secundario.

Botón de Acción.

No deberán crearse nuevos estilos sin una justificación clara.

---

# Tarjetas

Todas las tarjetas deberán compartir la misma estructura visual.

No deberán existir veinte diseños distintos para resolver el mismo problema.

---

# Fotografías

Las fotografías serán uno de los activos más importantes del proyecto.

Todas deberán:

Mantener la misma calidad.

La misma iluminación.

La misma proporción.

El mismo estilo.

No deberán mezclarse fotografías de diferentes estilos.

---

# Iconografía

Los iconos deberán ser sencillos.

Minimalistas.

Coherentes entre sí.

Nunca deberán utilizarse iconos únicamente como decoración.

---

# Animaciones

Las animaciones deberán existir únicamente para mejorar la experiencia.

Nunca deberán distraer.

Nunca deberán ralentizar la navegación.

---

# Responsive

Todo componente deberá diseñarse primero para dispositivos móviles y posteriormente adaptarse a pantallas grandes.

La experiencia móvil tendrá la misma importancia que la versión de escritorio.

---

# Regla principal

Antes de agregar un nuevo componente deberá responderse la siguiente pregunta:

¿Este componente realmente mejora la experiencia del usuario?

Si la respuesta es no, no deberá desarrollarse.
